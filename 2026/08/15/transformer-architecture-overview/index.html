Transformer 整体架构：三种注意力，一条数据流

文章发布时间:
2026-08-15

把 Transformer 那张图拆开看，其实只有两件事：编码器负责「让每个词看全整句」，解码器负责「看着全句 + 自己已写的前缀，一个字一个字往下猜」。剩下的残差、归一化、前馈层，都是为了让这件事堆得起来、训得稳定。

整理自 B 站视频：Transformer 第一课：整体架构

一句话概括

Transformer 没有换掉 seq2seq 的骨架，换掉的是信息在序列里流动的方式：从「按时间步往前传」变成「每个位置直接和所有位置建立联系」。

它站在谁的肩膀上

2017 年 Google 的《Attention Is All You Need》提出 Transformer，最初还是解决 seq2seq 问题（比如英译中），但它做了两件前人做不到的事：

  • 模型能理解的序列长度大幅变长；
  • 支持 GPU 并行，大规模训练成为可能。

之后 BERT、GPT、T5 都建在它上面，再往后扩散到视觉、语音、多模态——今天说的大模型，架构底子基本都是它。

把「变的」和「不变的」分开看最清楚：

变了吗 说明
encoder-decoder 骨架 没变 左边编码、右边解码，数据流和 seq2seq 一致
注意力「按需求查询已有信息」的思想 没变 Q 表达诉求，K 接受匹配，V 提供内容
信息在位置间怎么流动 变了 不再靠循环传递，靠自注意力直接两两建立联系
生成上下文表示的方式 变了 编码器内部、解码器内部各自的算法完全不同

数据流全景

先不看细节，只看数据从哪进、到哪出：

步骤 发生了什么
1 输入文本做 embedding，变成向量
2 加上位置编码（positional encoding），让模型知道谁在前谁在后
3 进编码器，逐层生成上下文表示，最终提供给解码器当 K 和 V
4 解码器一边读编码器的输出，一边读自己已生成的内容（目标前缀）
5 线性层把隐藏表示映射到词表大小，得到每个词的分数（logits）
6 softmax 变成概率，按策略（贪心 / 温度）选一个 token 输出
7 输出的 token 贴回目标前缀，回到第 4 步，直到生成 EOS

看着和「带注意力的 seq2seq」几乎一样——确实一样，差别全在第 3、4 步内部。

输入层：为什么必须加位置编码

RNN 是一步一步算的，天然知道顺序。自注意力是同时处理所有位置的，快是快了，但顺序依赖也消失了：给它「狗咬人」和「人咬狗」，它看到的是同一堆词。

所以架构图里那个加号不是装饰：

embedding 不直接进编码器，必须先和位置向量相加。之后每一层才知道：这个词在第几位。

编码器内部

编码器有两大件，分工很清楚：

部件 干什么
Multi-Head Self-Attention 让每个 token 和其他所有 token 交换信息：我和谁相关、该关注谁
Feed Forward Network 把交换来的信息再加工成更有表达力的特征

外面套的还是那两样：残差连接 + 层归一化。

Self-Attention：每个词都看一遍全句

RNN 里，后面的词想知道前面有什么，只能靠前面的状态传过来——序列一长，信息就淡了，而且必须串行。

自注意力让每个词直接和句子里所有词（包括自己）算一遍关系，得到权重：

关键是它没有依赖：love 算自己的注意力时，不需要等 i 先算完；四个词的计算可以同时进行。整句一起做就是一次矩阵乘法，这正是它能吃满 GPU 的原因。

因为 Q、K、V 全都来自同一个序列（自己查自己），所以叫 self-attention。算完之后，每个位置都得到一个「理解了整句」的向量。

Multi-Head：换个角度看同一句话

一组参数学一遍可能不够，于是用多组参数并行做注意力，每组叫一个 head。每个 head 从不同的表示子空间提取信息，最后把各 head 的输出拼接融合。

这个思路在 CNN 里见过：一个卷积核提一类特征，多个卷积核就能看到不同的东西。多头注意力没有引入新机制，只是并行的多个、不同角度的注意力。

Add & Norm：让深堆叠训得动

架构图上有两处 N×，意思是编码器和解码器都是叠了 N 层，论文里 N=6。

层一多就有两个老问题：参数暴涨、信息在连续变换中衰减；而且各层输出分布会漂移。对策就是每个子层外面套一层：

  • x + Sublayer(x)：残差连接，给梯度留一条直通路；
  • LayerNorm：把分布拉回稳定区间。

这里还有个小知识点，容易混：为什么 NLP 用 LayerNorm 而不是 BatchNorm？

BatchNorm LayerNorm
归一化维度 一个 batch 里「同一特征」跨样本 单个 token 自己的整个向量
NLP 里的问题 不同句子的第 1 个 token 之间没什么关系，凑一起归一化意义不大 同一个 token 的各维表示高度相关，按它归一化更合理

FFN：先睁大眼睛看，再放回来

自注意力解决的是「读谁的信息、读多少」，但读来的东西还不能直接当输出用，得再加工一次。

FFN 就是个两层的小网络：

先升维到 4 倍（论文里 512 → 2048），做非线性激活学更复杂的特征，再降回原维度。所以经过 FFN，维度不变。升维那一步相当于「睁大眼睛多看一些特征」，降回来是「再提炼一遍」。

之后照例再过一次 Add & Norm，编码器一层就结束了。

解码器内部

解码器的任务是：看编码器的输出 + 自己已经生成的前缀，预测下一个 token。

这里的第一层和编码器长得几乎一样，只多了一个词：masked。

因果掩码：不许偷看后面的答案

训练时用 teacher forcing，目标句子是一次性全喂进去的。如果翻译到「我喜欢」时，模型能看见后面的「深度学习」，那预测必然全对，训练就没意义了。

所以要把「当前位置之后」的内容遮住：预测第 3 个词，只能看前 2 个。

注意力种类 谁在看谁 有没有掩码 用在哪
Self-Attention QKV 都来自自己 无 编码器
Masked Self-Attention QKV 都来自自己 有（因果掩码） 解码器第一层
Cross-Attention Q 来自解码器，K/V 来自编码器 无 解码器第二层

编码器为什么不用遮？因为编码时整句本来就是已知的——翻译时当然要把英文看全，遮住反而没法理解。

顺带解释一下为什么解码器必须遮、而且要遮得这么细：并行。Transformer 一次把所有位置一起算，所以只能靠掩码来保证「每个位置只看自己前面」。这就是因果掩码存在的全部理由。

Cross-Attention：问题在这里，答案在编码器

交叉注意力的计算形式和普通注意力一模一样，只有 QKV 的来源不同：

  • Q：来自解码器自己（对目标前缀做完掩码自注意力后的上下文表示）——「我下一步想要什么」；
  • K / V：来自编码器——「原文里有哪些内容可供匹配」。

所以它叫 cross：查询在解码器，参照在编码器。架构图上那个位置正好画着两个箭头（K 和 V 从左边过来）、一个箭头（Q 从下面上来），看懂了箭头就看懂了这个模块。

顺便说，seq2seq 那节课里的注意力其实就是交叉注意力，只是当时没给它起这个名字。

输出：线性层 + softmax

解码器叠完 N 层后，每个目标位置得到一个隐藏表示，但它还是向量，不是词。

步骤 输出 含义
Linear logits（维度 = 词表大小） 每个候选词的分数
Softmax 概率分布（总和为 1） 每个候选词的概率
采样策略 一个 token 贪心 / 温度采样 / beam search

选出的 token 贴回目标前缀，进入下一轮。遇到 EOS 就停。

一个常见误解：并行是训练的，不是推理的

「Transformer 能并行」这句话经常被误读：

阶段 能不能并行 原因
编码（训练和推理都算） 能 输入序列完全已知，位置之间无依赖
训练时的解码 能 teacher forcing，目标序列整段已知
推理时的生成 不能 下一个 token 依赖上一个，只能自回归逐个吐

所以今天各种 chat 工具仍然是一个字一个字往外冒——那不是没优化，而是自回归的物理限制。

小结

  1. 骨架没变：还是 encoder-decoder，还是「查询-匹配-取内容」的注意力思想。
  2. 变的是信息流动：位置之间不再靠循环传递，而是直接两两计算。
  3. 编码器两大件：self-attention（交换信息）+ FFN（加工特征），每件都套残差和层归一化。
  4. 解码器三层注意力：掩码自注意力（看自己的前缀）、交叉注意力（看编码器）、再 FFN。
  5. 位置编码不是装饰，是并行化后保住顺序的唯一手段。
  6. 收益有两个：长距离依赖的路径变短、摆脱循环依赖可以并行；代价是参数量暴涨——不过有了 GPU，这笔账才算得过来。

下一节的重头戏是自注意力本身究竟怎么算，最后会手搓一个 mini transformer。

理解 Transformer 的关键，不是记住那张图有几个方框，而是想清楚一件事：序列里的信息，是怎么通过自注意力直接流动的。
