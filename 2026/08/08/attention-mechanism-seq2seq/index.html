注意力机制：从 seq2seq 的固定向量到 Transformer

文章发布时间:
2026-08-08

注意力机制不是凭空冒出来的新结构，它只是把 seq2seq 里「只交出一个固定上下文向量」改成了「每一步都回头查一遍原文」。就这一下，序列长度、词序对齐、并行化三件事全松动了，Transformer 才有地方落脚。

整理自 B 站视频：注意力机制：大模型前夜的最后一块拼图

一句话概括

seq2seq 的问题不是 RNN 太弱，而是它被迫把所有信息压进一个固定长度的向量；注意力做的事，是把这个「一次交底」换成「按需检索」——解码每一步都用不同的权重回看编码器的全部隐藏态。

先看 seq2seq 卡在哪

seq2seq 是编码器-解码器思想的一个实现，本质上把「一个序列」转成「另一个序列」：长度可以不等，位置也可以不对齐。机器翻译就是它最典型的任务。

它的工作方式是串行的：

  1. 编码器依次读入 i love deep learning 的每个 token；
  2. 每读一个产生一个隐藏态 H1…Hn；
  3. 最后只把最后一个隐藏态当作固定长度的上下文向量交给解码器；
  4. 解码器也是 RNN，根据这个向量一步一步吐出译文。

瓶颈就写在这一步上：固定长度的上下文向量。

序列长度 256 维上下文向量能表示多少
一句话 基本够用
一段话 开始丢信息
一部小说 严重损失，越靠前的内容丢得越狠

后来的 LSTM、GRU 用门控机制增强了保存长期信息的能力，但出口仍然是「一个固定长度的向量」——只是缓解，没有解决。让机器翻译一部小说，按这个架构信息损失必然过大。

人的翻译方式给的灵感

人翻译长文时不背全文。人是把原文放在手边，翻到哪就回头看哪：这一段对应原文哪几句，就多看几眼，其余少看。

这个动作换成模型语言就是：

  • 编码器每一步的隐藏态 H1…Hn 其实都还在，为什么要只取最后一个？
  • 解码器生成不同的词时，能不能以不同的权重参考所有这些隐藏态？

于是信息传递方式改了，整体骨架没变：编码器照旧，解码器还是 RNN，只是每一步不再只看那一个静态向量，而是对全部隐藏态做一次加权。

一个完整循环就是：当前解码状态 → 和每个编码状态打分 → softmax 成权重 → 加权求和 → 拼回解码状态 → 预测下一个词。

走一遍「i love deep learning」

编码器读出四个隐藏态 H1..H4，解码器已经生成了「我喜欢」，现在是 S3，要生成「深度」：

编码位置 隐藏态 注意力权重
i H1 0.07
love H2 0.06
deep H3 0.78
learning H4 0.09

c3 主要来自 H3，所以下一个词是「深度」的概率最高。接着到 S4 生成「学习」，权重又会向后面几个位置偏移——编码结果 H1..H4 自始至终没变，变的是每一步的权重和上下文向量。

这就是它相对「固定上下文向量」最核心的改进。

软对齐：词序不对齐也没关系

把 There's the cat under the table 翻成「桌子下面有一只猫」，注意力的热力分布大致是：

译文 最相关的原文位置
桌子 table
下面 under
猫 cat
有一只 is / a

注意「桌子」对应的是原文中间偏后的 table，而 table 又不是最后一个词；「猫」对应的是中间的 cat。位置完全不对应，注意力照样能找到该看的地方。

这种用连续权重表示的对应关系叫软对齐：不要求一个目标词只对应一个源词，允许多个输入位置以不同权重同时参与。也不是人工标注出来的，而是训练时为了降低翻译误差，模型自己学会了把高权重分配到位。

实验：把句子拼长，差距立刻出现

用 AND 把两个句子拼起来，让模型翻译更长的输入。两个版本唯一的区别在解码器：

  • 无注意力：只拿最后一个隐藏态做解码器初始值；
  • 有注意力：拿到全部隐藏态，预测时多做打分、归一化、加权求和三步。

各自训练 35 轮后的匹配率：

输入 无注意力 有注意力
单个子句 100% 100%
两个子句 40.4% 100%
三个子句 几乎为 0 97.5%

多出来的这几步运算，参数只增加了约 4.6%。所以差距不是「模型容量」问题，而是信息通道问题——固定向量那道闸门太窄。

消融：输入倒序这个技巧失效了

seq2seq 时代有个训练技巧：把输入序列倒过来。因为只取最后一个隐藏态，倒序能让「原文第一个词」离解码起点更近一点，缓解长距离遗忘。

加了注意力之后再做消融：

模型 输入翻转的影响
纯 seq2seq 差别很大
seq2seq + attention 翻转与不翻转分数一样

因为每一步都是动态计算「该关注谁」，跟具体位置无关了——你在哪儿，我都能算出该不该看你。

换个说法：注意力就是可学习的信息检索

把上面三步抽象出来，就是 Q / K / V：

角色 在 seq2seq + attention 里是谁 作用
Query（Q） 解码器当前状态 s_t 表达「我现在需要什么」
Key（K） 编码器全部隐藏态 H1..Hn 接受查询、算匹配分数
Value（V） 同样是 H1..Hn 按权重取出的内容

一个常见疑问：K 和 V 都是同一批隐藏态，凭什么能扮演两个角色？因为它们在参与运算前会各自乘一个不同的权重矩阵，被投影成不同的表示。这两个（以及 Q 的）投影矩阵都是训练学出来的，不是人指定的——所以才说注意力是可学习的信息检索。

它解决了什么，又没解决什么

解决了：

  • 不再用固定长度向量概括全部信息，而是按需动态访问各个位置；
  • seq2seq 能处理的有效序列长度大幅提升；
  • 不再依赖输入顺序上的技巧（倒序失效）。

没解决：

  • 循环结构还在，仍然按时间步串行推进，训练慢；
  • 长度再长依然受限；
  • 解码器仍然要一步步等上一个状态。

但注意力的抽象本身是通用的：只要有「某个位置需要从一组候选信息里找相关内容」这件事，就可以用 QK 匹配算权重、再用权重汇总 V。 它不绑定编码器-解码器的结构。

通向 self-attention：把那句 all you need 读懂

既然解码器能直接访问编码器的任意位置，那模型内部的不同位置为什么不能互相访问？

让 Q、K、V 全部来自同一个序列：每个位置既发起查询，也接受匹配，也提供内容——这就是 self-attention（自注意力）。

关键在于它顺手解决了 RNN 的另一个死结：

RNN self-attention
依赖关系 下一步依赖上一步，必须串行 各位置直接两两计算，无依赖
并行度 低 一次算完，能喂满 GPU
训练速度 慢 快，参数量也敢往上堆

2017 年《Attention Is All You Need》提出 Transformer，核心就是 self-attention，然后把循环结构整个删掉。

论文标题其实是句回答：以前光有注意力不够，还得有循环架构去算那些隐藏态；现在不要循环了，只要注意力——所以「attention is all you need」。

和当年 seq2seq 把编码器-解码器从统计机器翻译的一个打分组件，变成整个模型的骨架，是同一种「组件升格为架构」的路径。

小结

  1. seq2seq 的瓶颈是固定长度的上下文向量，LSTM/GRU 只是缓解。
  2. 注意力 = 解码时用动态权重回看编码器全部隐藏态：打分 → softmax → 加权求和。
  3. 多个子句的实验里，无注意力 40.4% / 几乎为 0，有注意力 100% / 97.5%，参数只多 4.6%。
  4. 它带来的是软对齐：词序不必对应，权重自己学出来。
  5. 抽象成 Q/K/V 之后，它就是一个可学习的信息检索机制，能脱离 seq2seq 存在。
  6. 让 Q/K/V 同源，就是 self-attention；去掉循环，就是 Transformer。
