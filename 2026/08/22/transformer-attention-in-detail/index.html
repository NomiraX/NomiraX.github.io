注意力到底在算些什么：三种注意力，一套公式

文章发布时间:
2026-08-22

上一节把架构图拆成了方框，这一节拆到方框里面：attention 到底在干什么、为什么一个模型里要连着用三次、为什么缓存的是 KV 而不是 Q。

整理自 B 站视频：Transformer 注意力究竟在做什么

一句话概括

attention 做的是同一件事：给每个 token 重新生成一个表示——原来它只包含自己的语义和位置，算完之后它带着整句里跟它相关的信息。

三种注意力，一套公式

Transformer 里出现的是三种注意力，但计算方式完全一样，区别只在 Q、K、V 从哪里来：

注意力 Q 来自 K、V 来自 有没有掩码 位置
自注意力 自己序列 自己序列 无 编码器
掩码自注意力 自己序列 自己序列 有 解码器第一层
交叉注意力 解码器 编码器 无 解码器第二层

记住这张表，后面所有的困惑基本都能自己回答：变的是来源，不变的是算法。

定义：让每个词「认识一下」整句话

一个词的含义要靠上下文才能确定。经典例子：

The animal didn’t cross the street because it was too tired.

这里的 it 指 animal；换成 “it was too wide”，it 就指 street 了——位置一模一样，指向的对象变了。

但 embedding 之后，每个 token 只有自己的语义 + 位置，跟句子还没有关系。注意力的任务就是让它们发生关系：

  • 先算每个 token 和其他所有位置的匹配程度——和谁最相关；
  • 再按这个匹配程度去读取、汇总信息；
  • 于是新生成的表示里，除了自己，还混进了相关的其他词。

可以想象成上色：进入 attention 之前，每个 token 的向量是纯色（只有自己）；出来之后，颜色是混合的——it 的向量里 animal 的成分最重，所以连线最粗。

这就是 attention 的定义里那句话：为每个 token 生成新的上下文表示。

为什么一个模型里要连着用好几次

这是最常见的困惑。答案藏在 seq2seq 和 Transformer 的区别里。

两者做的事很像：把一个输入序列 A 变成输出序列 B。步骤也能概括成同样四步：

步骤 干什么
1 理解输入序列，得到它的上下文表示
2 理解输出序列里已经生成的部分
3 拿当前输出状态去看输入序列，按需取信息
4 融合，预测下一个 token

差别只在第 1、2 步的「理解」是怎么实现的。

  • seq2seq：靠 RNN 一步步跑出隐藏态，拼成矩阵。注意力只在第 3 步用一次——用解码器状态当 Q，编码器隐藏态当 K/V。
  • Transformer：把「理解」这件事本身也交给了注意力。第 1 步是编码器的自注意力，第 2 步是解码器的掩码自注意力，第 3 步才是交叉注意力。

所以不是「多用几次」，而是原本由 RNN 承担的活儿，现在也被注意力接手了。

QKV：三种视角看同一个矩阵

为了算出位置之间的关系，模型学了三组参数矩阵 W_Q、W_K、W_V，把输入投影成三个新矩阵：

同样的输入，三种问法：

矩阵 回答的问题 打个比方
Q 我要更新自己时，最想查什么信息 我的检索需求
K 别人来匹配我时，能拿到的特征是什么 论文的摘要
V 真被匹配上之后，我能提供的完整内容 论文的正文

这篇论文的类比很好用：K 是摘要，你先看摘要判断要不要读；V 是正文，决定读了才拿走。而矩阵每一行仍对应原序列的一个位置，只是信息被投影到了不同视角上。

一个 token 是怎么被算出来的

拿 learning 举例，五步：

  1. 打分：用 learning 的 Q 和所有位置的 K 做点积（本质是余弦相似度），得到四个分数。
  2. 缩放：除以 √d_k。不除的话数值区分度太大，softmax 后几乎变成 one-hot，梯度趋近 0，训练不动。
  3. 归一化：softmax 变成权重，加起来等于 1。
  4. 加权求和：按权重去 V 里取对应比例的信息，累加。
  5. 得到新表示：这个向量里带着整句的上下文。

掩码自注意力：训练时不许偷看答案

解码器第一层的 QKV 也全来自自己，但多了一个「掩码」。

训练用 teacher forcing：目标句整段一次性喂进去，因为要并行、要快。问题来了——预测第 3 个词时，模型已经能看见第 4、第 5 个词的正确答案，那它根本不用学，直接抄就行。

这叫信息泄露。解决办法是把当前位置之后的内容遮掉：

加了 -∞，softmax 之后这些位置的权重就是 0，相当于看不见。被遮住的部分不是没用——反向传播算损失时还要用。

这样训练时的可见范围就和推理时一致了：推理到第 t 个 token，本来也看不到 t+1。

交叉注意力：问题在解码器，答案在编码器

这一层才是真正的「交叉」：它横跨编码器和解码器。

  • Q：来自解码器掩码自注意力的输出——「我现在想生成下一个词，需要什么信息」；
  • K/V：来自编码器的输出——「原文里有什么可供匹配」。

架构图上这里的三个箭头要看清：两个从左边（编码器）过来，一个从下面（解码器）上来。

注意每个注意力模块都维护自己的投影矩阵——编码器的输出虽然被反复使用，但每次都要用交叉注意力自己的 W 重新投影一遍。

一个 token 的诞生过程

推理时是逐个生成的，走一遍就懂了：

轮次 输出序列 发生了什么
1 BOS 掩码自注意力只看得见 BOS，得到 Q，去交叉注意力查编码器输出，预测出「我」
2 BOS 我 序列变长，重新算掩码自注意力，Q 更新，再查编码器，预测「喜欢」
3 BOS 我 喜欢 同上，预测「深度」
4 BOS 我 喜欢 深度 同上，预测「学习」
5 … 学习 预测出 EOS，结束

两个细节：

  • 编码器只跑一次，而且是并行的——输入序列完全已知，没必要重复算。
  • 训练时解码也是并行的：因为有 teacher forcing，整段答案都给了，一次矩阵运算就能算出所有位置的输出。只有推理必须自回归。

这就是 Transformer 训练比 RNN 快得多的根本原因。

为什么有 KV cache，没有 Q cache

做推理和 Agent 开发时天天听到 KV cache，但从来没听说过 Q cache。理解了上面的过程，答案是自然的。

K 和 V 会被反复使用，Q 只用一次。

位置 第 t 步用完还继续用吗 能不能缓存
Q（当前 token 的查询） 不能，下一步就换成新的 Q 没必要
K/V（历史 token 的键值） 能，后面每一步都要查 应该缓存

所以 KV cache 缓存的是两处：

  1. 交叉注意力的 K/V：来自编码器，整个生成过程只算一次，内容永远不变；
  2. 掩码自注意力的 K/V：来自已生成的 prefix，每步只多一个 token，新的 append 进去即可，前面的不用重算。

序列生成到第 1000 个 token 时，前面 999 个的 K/V 都在缓存里，只有第 1000 个需要新算。省下的就是这些重复计算。

顺带解释 prompt cache

同一套逻辑还能解释 Agent 开发里那条工程纪律：把系统提示词、工具定义、公共上下文放在 prompt 最前面，并保持稳定。

原因很直接：每个位置的中间状态都依赖它前面的内容。如果前缀的第 10 个 token 变了，从它往后的所有状态都失效，缓存全废。反过来，前缀越稳定，能复用的范围越大——成本就是这么降下来的。

小结

  1. 三种注意力计算方式一样，只是 QKV 来源不同。
  2. attention 的本质是一次序列表示的更新：从「只表示自己」变成「融合了整句里相关的信息」。
  3. Q 是检索需求，K 是匹配用的摘要，V 是被取走的内容。
  4. 缩放除以 √d_k 是为了让 softmax 不要过尖、梯度别消失。
  5. 掩码是为了防止 teacher forcing 时信息泄露；被遮部分仍用于算损失。
  6. 编码器只算一次、训练时全并行；推理必须自回归，所以才有 KV cache。
  7. 缓存的是会被复用的 K/V，不是只用一次的 Q；prompt 前缀稳定是同一个道理。

理解了注意力，剩下的（多头、位置编码）都只是在这套机制上做工程优化。下一节就是多头注意力。
