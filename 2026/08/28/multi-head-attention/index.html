多头注意力：把一个 512 维空间切成八个 64 维

文章发布时间:
2026-08-28

架构图上那三个方框写的其实是 Multi-Head Attention，不是 Self-Attention——这个缩写骗过不少人。多头的全部秘密就两件事：八套独立的投影矩阵，和切片而不是复制。

整理自 B 站视频：Muti-Head Attention：多个角度提取特征

一句话概括

论文里是 8 个头；模型做大以后可以更多，这只是一个可调的超参。

为什么要多个角度

一个头只有一套投影，意味着所有类型的关系都被挤在同一个表示空间里。

还是那句话：

The animal didn’t cross the street because it was too tired.

在同一个 it 上，不同的头可能盯住完全不同的东西：

头 最关注 学到的关系
head 1 animal 指代关系——it 到底指谁
head 2 was 句法结构——这个句子怎么组织起来的
head 3 tired 语义——这个动物最后是什么状态

三件事都重要，但一个 64 维的投影空间塞不下全部的区分度。多套投影等于多套坐标系，各自在自己的空间里判断「谁和我最相关」，最后把三种理解拼起来。

和 CNN 是同一个思路

这种做法在深度学习里并不新鲜，最典型的就是卷积：

CNN 多头注意力
一份输入 一张特征图 一个序列矩阵
多套参数 多个卷积核 多个 head
每组只提取一类特征 是 是
最后合并 通道拼接 Concat + 线性层

一个卷积核只认一种模式，一层里放多个核就能同时看纹理、看边缘、看颜色。多头注意力是同一个逻辑换个场景。

但别过度解读。 说某个 head 负责「指代」、某个负责「语法」，那是人类的比喻；实际训练出来的每个头学什么，是模型内部自己决定的，不一定有可解释的人类语义。上面那张表是为了讲清楚「不同空间看不同东西」，不是论文结论。

参数量怎么没爆：是切片，不是复制

这是最容易误解的地方。8 个头并不意味着要把 512 维变成 8 × 512，那样计算量直接翻八倍。

Transformer 的做法是切分表示空间：

单头 8 头
d_model 512 512
每个头看到的维度 512 64（= 512 / 8）
每个头算出的注意力矩阵 N × N N × N
输出拼接后 512 8 × 64 = 512
再乘 W_O — 变回 512

关键点：

  • 序列长度没变。原来是 N 个 token，现在还是 N 个 token，注意力矩阵仍然是 N×N，描述的还是这 N 个位置彼此的关系。
  • 变的是每个 token 的表示维度，从 512 变成每个头 64。
  • 每个头只看 64 维，相当于把「一次看全部」换成「八次各看一部分」，总计算量和单头基本持平——这本身就是一种并行。

拼接之后为什么还要乘 W_O

理论上拼完就有 512 维了，为什么还要多做一次线性变换？

因为 Concat 只是把八段并排放：第 1–64 维是 head 1 的信息，第 65–128 维是 head 2 的，各管各的区间。段与段之间没有任何交互，信息并没有真正混在一起。

加一层 W_O 之后，输出的每一个维度都同时组合了所有 head 的信息，八种理解这才被融合成一个整体。

打个比方：Concat 是把八份报告装订成一册，W_O 才是把它们综合成一份结论。

小结

  1. 架构图方框里写的是 Multi-Head Attention，单头只是它的一个组成部分。
  2. 8 个头 = 8 套独立的 WQ/WK/WV，各自算一遍普通注意力。
  3. 目的是多角度看同一句话：指代、句法、语义可以分别在不同空间里被捕捉。
  4. 计算量没翻八倍的关键是切片：512 维切成 8 个 64 维，而不是复制八份。
  5. 注意力矩阵始终是 N×N，变的是 token 的表示维度，不是序列长度。
  6. Concat 只是并排，W_O 才让八路信息真正融合。
