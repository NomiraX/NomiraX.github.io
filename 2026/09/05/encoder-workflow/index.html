编码器工作流程：一份表示反复更新，维度只在两处变

文章发布时间:
2026-09-05

写 Transformer 代码最容易晕的地方不是公式，是维度和形状。这篇把编码器从输入到输出走一遍，只盯一件事：什么东西在变，什么东西一直不变。

整理自 B 站视频：手搓 Mini Transformer 前要知道的编码器工作流程

一句话概括

编码器不是把整句话压成一个固定向量，而是把同一份序列表示反复更新 N 次——进去是 N × d_model，出来还是 N × d_model，只是每一行都融合了整句的信息。

输入：两个加号，维度不变

两个要点：

  • 行数 N = 序列里有多少个 token；
  • 列数 d_model = 论文里 512，自己手搓可以改成 64 之类，运行更快。

相加只改变数值，不改变形状。这个矩阵是整个编码器里始终被操作的那一份数据。

进入编码器时，每个 token 的向量只包含「自己是什么」和「自己在第几位」——它还不知道句子里其他词的情况。

编码器的两个部件

部件 作用 会不会跨 token 交换信息
多头自注意力 让 token 互相认识、交换信息 会
前馈网络（FFN） 对每个 token 自己再加工，提取更丰富的特征 不会

两个子层外面都套了「残差 + 层归一化」，最后再整体叠 N 层（论文里 6 层）。

第一站：多头自注意力

Q、K、V 都来自同一份输入，所以叫自注意力。每个 token 用自己的 Q 和全序列的 K 算匹配，再按权重去 V 里取信息，得到新表示。

多头版本做了一次形状变化：

512 被切成 8 份 64 维，各头独立算，最后拼回 512 再做一次线性变换。

注意：进出形状完全一样（N × d_model），变的是每一行的内容——进去时 it 只表示它自己，出来时它的向量里已经掺进了 animal、tired 这些信息。

残差：学的不是新表示，是修正量

为什么要加这个 X？视频里用打高尔夫打比方：没人指望一杆进洞，每次往前推一点，最后就进去了。

对模型来说：

  • 子层要学的不是「一个全新的表示」，而是「在原有表示上补多少修正」；
  • 如果这一层没什么可补的（参数已经差不多对了），把输出压到接近 0 就行——学「零」比学「恒等映射」容易得多；
  • 反向传播时梯度有直通路，深层也训得动。

层归一化：横向的，不交流

LayerNorm 是对单个 token 的 512 维特征做归一化，不是跨 token 做。

所以它和自注意力有本质区别：

跨 token 作用
自注意力 会 交换信息
层归一化 不会 把数值分布拉稳

多层反复迭代，数值容易震荡，归一化就是为了让每层的输入落在稳定区间。

一个现代改动：Pre-Norm

论文的原始顺序是 Post-Norm——先残差相加，再归一化：

但现在的大模型普遍改成 Pre-Norm——先归一化，再送进子层：

原因：深层模型里 Pre-Norm 训练更稳、更容易收敛。不过手搓代码时，视频建议还是照论文的 Post-Norm 实现，知道这个差异就行，看到新模型的图时不至于看不懂。

第二站：FFN，先升维再降维

三步：线性变换升维、非线性激活、线性变换降维。

为什么先升维？维度越多，能表达的特征组合越多；自注意力已经把「哪些信息相关」取回来了，FFN 负责在这个基础上做更复杂的非线性加工。升完再降回来，是为了保证输出维度还是 d_model，也让参数量不至于无限膨胀。

两个容易被忽略的事实：

  • 论文用 ReLU，现代模型多用 GELU / SwiGLU；
  • FFN 的参数量通常比同一层的注意力还大，因为它中间宽了四倍。

还有一种常见误解：FFN 是不是也在 token 之间传信息？不是。它对每个位置用的是同一套参数，各算各的，所以不交换信息——这跟 LayerNorm 一样，都是「横向」的操作。

一层编码器 = 四个公式

写代码时，这四行就是 EncoderLayer.forward 的全部内容。

维度只变两次

这是整篇最该记住的一句话：

位置 形状变化 说明
进编码器 N × d_model embedding + 位置编码
多头内部 N × 8 × 64 拆头，算完拼回
多头出口 N × d_model 恢复原状
FFN 内部 N × 4·d_model 升维，激活后降回
FFN 出口 N × d_model 恢复原状
每层出口 N × d_model 始终不变

只有拆头和 FFN 升维这两处会暂时变形，其余全是 N × d_model。 记住这个，手写代码时基本不会乱。

多层堆叠：同一份表示反复更新

每层用自己的注意力参数和 FFN 参数（参数共享就没意义了），上一层的输出直接当下一层的输入。

变化是渐进发生的：

层 这个 token 的向量里有什么
进第一层前 自己的语义 + 位置
过第一层后 融合了整句相关信息，并经过 FFN 加工
过第 N 层后 越来越丰富的上下文表示

层数可以自定义，论文里是 6。

输出：还是那个形状

形状一模一样，只是每行的内容从「只懂自己」变成了「懂整句」。这也是为什么编码器的输出可以直接交给解码器：它保持了一个序列，而不是压成一个向量。

这一点和原版 seq2seq 有本质区别：

seq2seq Transformer 编码器
输出 一个固定长度的上下文向量 长度 = N 的序列表示
信息 全句被压进一个向量 每个位置各自携带上下文

解码器的交叉注意力需要的 K 和 V，就是拿这份 H 分别过两个线性变换得到的。

小结

  1. 编码器的输入、输出形状都是 N × d_model，中间只有拆头和 FFN 升维两处临时变形。
  2. 自注意力负责跨 token 交换信息，FFN 负责单 token 深加工，两者分工明确。
  3. 残差学的是修正量，让「学零」代替「学恒等映射」；层归一化按 token 横向做，不交流信息。
  4. 论文用 Post-Norm，现代模型普遍用 Pre-Norm。
  5. 编码器不压缩序列——输出仍是一整排向量，这正是它能给交叉注意力提供完整 K/V 的原因。
  6. 下一站是解码器：那里的矩阵是逐行长大的。
