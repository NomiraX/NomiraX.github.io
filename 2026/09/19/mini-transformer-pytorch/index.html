手搓 Mini Transformer：用 PyTorch 写一个英译中翻译器

文章发布时间:
2026-09-19

前面几篇把编码器、解码器、注意力、位置编码都拆开看过了，这一篇把它们拼起来，跑一个真能翻出中文的 mini transformer。

整理自 B 站视频：一小时彻底掌握 Transformer

先说清楚简化了什么

完整的 Transformer 实现很复杂。为了把注意力放在「原理有没有对上」，这个实现做了几处刻意简化：

简化 后果
每次只训一个句子，不做 batch 不需要 padding，也不需要 padding mask
用 Python 循环 + 普通矩阵乘 CPU 就能跑，不需要 GPU / MPS
超参数全部调小 D=32、heads=2、层数=2、最长 32
语料只有 8 句 几十轮就收敛，方便看效果
不做 KV cache 推理时每步重算历史，慢，但对应论文逻辑

唯一没简化的是结构：每一处维度和论文一一对应。这也是为什么手搓一遍之后，读真实模型的代码会顺很多。

三个符号先约定好

符号 含义
S 英文输入（source）的 token 数
T 中文前缀（target）的 token 数
D 整个模型统一的维度，也就是 d_model

整体分四块

代码最终拆成这些类：PositionalEncoding、TokenEmbedding、attention、MultiHeadAttention、FeedForward、EncoderLayer、Encoder、DecoderLayer、Decoder、MiniTransformer。核心创新部分全部手写，残差和 LayerNorm 直接调 PyTorch API。

两个关键认知：

  • token id 只是一个索引，不是向量。3 和 4 挨着，不代表这两个词语义接近。
  • 语义在 embedding 表里：模型拿 id 去那张 [词表大小, D] 的矩阵里查一行。这张表是训练出来的。

<BOS> 和 <EOS> 只加在中文侧，因为只有目标序列需要「开始」和「结束」。这里不做 batch，所以不需要 <PAD>；语料里也没有生词，所以不需要 <UNK>。

Teacher forcing：把标签错开一位

解码器要学的规律是「给前 n 个词，预测第 n+1 个」。所以一句话要同时变成输入和标签：

也就是 input = target[:-1]、label = target[1:]。这样序列自己就能给自己当监督信号，这种方法叫 teacher forcing。

位置编码

D 维分成 D/2 组，第 i 组：

register_buffer 这一行很重要：位置编码是算出来的常量，不该被梯度更新。加上它，model.parameters() 自然不会把它混进来。

Embedding：先乘 √D 再加位置

为什么乘 √D？位置编码的数值量级固定，如果直接和 embedding 相加，位置信息会盖过语义。乘上 √D 把语义放大，两者量级接近，语义仍然是主角——这是论文里的做法。

注意力的实现

用 -inf 而不是 0 遮罩的原因：-inf 过 softmax 得到严格 0，未来位置的权重彻底消失；如果填 0，softmax 之后仍然会分到一点权重。

多头注意力

D 被分成 HEADS 份，每份 d_k = D // HEADS。每个头有自己的一套 W_Q、W_K、W_V：

两个细节：

  • 拆头不是把 32 维切成 0–15 和 16–31，而是各自过投影矩阵。所以拼回来之后必须再过一次 wo 才能恢复正常的表示——顺序本来就不是按位置切的。
  • 每个头的参数互相独立，这就是「多角度理解同一句话」的来源。

FFN：先升维，再降维

对每个位置用同一套参数各算各的，所以 FFN 不在 token 之间传信息。

编码器的一层

这里用的是论文的 Post-Norm：先残差相加，再归一化。两个 LayerNorm 必须分别 new 一次，共用一个就等于让两处强行共享参数。

解码器的一层

比编码器多两件事：因果掩码和交叉注意力。

注意交叉注意力不加因果掩码——原文整句都是已知信息，没有「未来」可言。

训练

因为 8 个句子实在太简单，十几轮之后损失就掉到 0.001 量级，交叉熵几乎为零，说明每个位置都预测对了。

推理：从 BOS 一个个往外挤

两个要点：

  • 只用 logits[-1]——最后一行对应「下一个 token」。前面各行虽然也算出来了，但推理时不需要。
  • 推理要 model.eval() + torch.no_grad()：不记梯度，也不需要 dropout（这里没用 dropout，但习惯要养成）。

和真实实现差在哪

差异 这个实现 真实训练
batch 一次一句 [B, N, D]，多一个维度
padding 不需要 句子补齐，另加 padding mask
计算 CPU 循环 GPU 张量运算
推理 每步重算全部历史 KV cache 复用
词表 手动切词 BPE / SentencePiece
规模 D=32、2 层 D=512+、6 层起

要实现 batch 版，本质上就是给几乎所有张量加一个 B 维，再处理 padding 的位置——麻烦，但原理没变。

小结

  1. 整个模型就是「embedding + 位置编码 → 编码器 → 解码器 → 输出投影」四段，中间反复出现的形状是 [N, D]。
  2. 词表负责把词变成 id，embedding 表负责把 id 变成向量，位置编码负责告诉模型「第几位」。
  3. teacher forcing 把目标序列错开一位，同一句话既是输入又是标签。
  4. 多头注意力的拆分靠投影而不是切片，所以拼回来之后要再过一次线性层。
  5. 解码器比编码器多两样：因果掩码（不许看未来）和交叉注意力（去查原文）。
  6. 训练和推理结构一样，区别在于是否已知答案、是否累计梯度、是否逐 token 循环。

这份代码跑通之后，就具备了读真实模型源码的基础。下一步是看 BERT、T5、GPT 怎么在「编码器 / 解码器 / 训练目标」上做不同的组合与取舍。
