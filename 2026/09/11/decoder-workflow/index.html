解码器工作流程：掩码、交叉注意力，和逐 token 的代价

文章发布时间:
2026-09-11

编码器一次性把整句看懂，解码器得一个字一个字往外挤。这篇把这个不对称讲清楚：为什么必须遮住未来、为什么每次只拿最新一行去预测、训练和推理到底差在哪。

整理自 B 站视频：Transformer 解码器工作流程

一句话概括

解码器的任务只有一个：看着编码器给出的原文 H，再看着自己已经写出来的部分，预测下一个 token。其余所有部件都在为这两件事服务。

两个不对称

编码器的输出是 H = S × d_model（S = 输入 token 数），它一次就算完了，因为输入整句都已知。

解码器在推理时必须从 BOS 开始逐个生成：

每生成一个 token，矩阵就多一行；列数永远是 d_model。

还有一点容易忽略：S 和 T 不一定相等。英译中时英文 20 个 token、中文 15 个 token，行数不同完全正常。

解码器的部件清单

部件 和编码器比 作用
embedding + 位置编码 完全相同 输入预处理
掩码多头自注意力 多了因果掩码 理解已生成的 prefix
交叉注意力 解码器独有 去查编码器的输出
FFN 完全相同 特征加工
残差 + 层归一化 完全相同 训练稳定
线性层 + softmax 解码器独有 变成词表上的概率

所以真正新的只有两样：掩码和交叉。

第一层：掩码自注意力

它的 Q、K、V 也都来自同一份输入（解码器自己已经生成的部分），本质上还是自注意力，只是多了一个遮罩。

为什么要遮？分训练和推理看：

阶段 后面的内容存在吗 遮罩有没有用
推理 不存在，还没生成 逻辑上不需要，但为了和训练一致仍保留
训练 存在（teacher forcing 整段喂入） 必须遮，否则等于作弊

训练时如果把完整的目标句一次性喂进去，模型在第 3 个位置就能直接看到第 4、5 个位置的正确答案——那它根本不用学预测，抄就行。这叫信息泄露。

解决办法是用 -∞ 把未来位置填掉：

-∞ 的好处是 softmax 之后正好是 0，等于完全看不到。

第二层：交叉注意力

这一层才是解码器真正「对外」的地方。

来自 含义
Q 解码器（掩码自注意力 + Add & Norm 之后的输出） 我下一步想要什么信息
K 编码器输出 H，经自己的 W_K 投影 原文里有什么可供匹配
V 编码器输出 H，经自己的 W_V 投影 匹配上之后取走的内容

为什么一定要看原文？因为只看自己已翻译的前缀，信息不够——翻下一个词时，你得回头看英文原句。

计算过程和普通注意力一模一样，只是投影参数是这套注意力自己的。所以同一个 H 被交叉注意力反复使用，每次都用它自己的 W 重新投影。

一个常被问的问题：为什么只用最新一行预测

推理时，每一步都把「整个已生成序列」送进注意力，但做预测时只用最新的那一行。

原因在于：最新那一行经过掩码自注意力之后，已经不是它自己了——它的向量里已经包含了整个 prefix 的信息。再加上交叉注意力给出的原文信息，足够预测下一个词。

这也解释了训练为什么快：训练时不需要一步步来，整个 T × d_model 矩阵一次送进去，一次算出所有位置的输出。

输出层：从向量到词

阶段 形状 含义
隐藏表示 d_model 特征向量
线性层输出 vocab_size（比如 10 万） 每个候选词的分数 logits
softmax vocab_size，和为 1 概率分布

logits 不是概率，只是打分；softmax 只负责把分数变成概率分布，它不决定选哪个词——选词是解码策略的事。

解码策略：概率之后怎么挑

策略 做法 特点
贪心 取概率最高的那个 最确定，容易重复、死板
温度 logits 除以 T 再 softmax T 小 → 分布更尖、更确定；T 大 → 更平、更有随机性
top-k 只在概率最高的前 k 个里挑 候选数量固定
top-p（核采样） 按概率排序累加，累计到 p 就截断 候选数量动态变化

实践里这些可以叠加：先用温度调整分布的陡缓，再用 top-k / top-p 把候选缩到一小撮，最后在里面采样。

写代码、做工具调用这类任务时温度通常设 0（要确定性）；写故事、做创意时才调到 0.2～0.8（要多样性）。

生成到 EOS 就停，整个目标序列就完成了。

训练 vs 推理：一张表看完区别

训练 推理
输入 完整目标序列，T × d_model 只有已生成的部分，逐步变长
QKV 一次全算出来 只用最新的 Q，K/V 从缓存取
注意力矩阵 T × T，加因果掩码 一行对历史，不需要遮（本来就没有未来）
输出 一次得到所有位置 每次只得到一个 token
步数 1 次前向 T 次前向
成本 便宜（并行） 贵（串行）

这也解释了为什么 ChatGPT 是一个字一个字往外吐：不是没优化，是自回归的物理限制。训练时代替这个过程的，就是 teacher forcing——把答案右移一位当输入，一次算完全部位置的损失。

批次与两种掩码

真实训练时还要多一个维度：

句子长短不一，所以要 padding：统一补到最长句，补的 token 叫 PAD。于是就有了第二种掩码：

掩码 遮住什么 用在哪
因果掩码（causal） 位置 j > i 的未来 token 掩码自注意力
Padding 掩码 补齐用的 PAD 位置 所有注意力

不加 padding 掩码，模型会把补出来的无意义 token 也当成内容参与运算。

小结

  1. 编码器并行算一次，解码器推理时逐 token 串行，矩阵一行行长出来。
  2. 掩码自注意力用来理解「我已经写了什么」，训练时必须遮未来，推理时只为架构一致。
  3. 交叉注意力是唯一「对外」的部件：Q 来自解码器，K/V 来自编码器。
  4. 预测只用最新一行，因为这一行经过注意力后已经携带了整个 prefix 的信息。
  5. 线性层把向量映射到词表，softmax 出概率，温度 / top-k / top-p 决定怎么挑。
  6. 训练一次算完（teacher forcing），推理 T 步（自回归）——KV cache 就是为了少算历史。
  7. 实际实现多两个维度、两种掩码：batch 维和 padding 掩码。
