位置编码：让 attention 知道谁在前谁在后

文章发布时间:
2026-09-02

自注意力为了并行，把「顺序」这个大前提弄丢了。位置编码就是那张补票：它不参与计算什么语义，只负责让每个 token 的向量里带上「我在第几位」。

整理自 B 站视频：位置编码：让注意力理解 Token 在序列中的位置

一句话概括

attention 只算两个 token 之间的关系，不知道它们相隔多远；位置编码的任务就是把「距离」塞进向量里，让点积自己就能算出远近。

一个被并行弄丢的前提

RNN 有个隐藏的好处，平时容易被忽略：它天生带着顺序。

token 必须依次进入模型，前一个位置算出隐藏态交给后一个，整个计算过程本身就是「谁先谁后」。代价是慢——前一步不走完，后一步动不了。

Transformer 反过来：整个序列拼成矩阵，一次算出任意两个 token 的关系。快是快了，但所有位置同时算，模型拿到的是一个集合，不是一个序列。

同样的三个词，换个顺序意思完全相反：

句子 意思
dog bites man 狗咬人
man bites dog 人咬狗

如果只做 embedding，这两句的 token 集合一模一样，attention 算出来的关系也一模一样。所以必须在第一次 attention 之前把位置补进去。

补法：加法，不是拼接

论文里的处理很朴素：

两个向量的维度都是 d_model（比如 512），直接相加。

一个自然的疑问：为什么不拼接？前半段放语义、后半段放位置，界限清清楚楚。

原因很实际：拼接会让维度翻倍。整个 Transformer 后面所有矩阵运算都是围绕固定的 d_model 设计的，输入维度一变，后面每层的参数、计算量全都要跟着改。相加能让维度保持不变，和后面所有模块严丝合缝地接上。

为什么不用 0、1、2、3 这种编号

这是最反直觉的一步。用人眼看，6 和 3 相差 3 一目了然；但模型不是这么工作的。

三个理由，从重要到次要：

原因 说明
Transformer 里没有减法 整个前向只做点积和矩阵乘法，6 - 3 这个操作它做不出来，数字本身承载不了「相差多少」
数值会失控 序列一长，位置编号涨到几万；embedding 的值通常只有 0.x～2.x 量级，一相加，语义几乎被位置信息淹没
归一化不好做 要做归一化就得先知道最长序列多长，而实际长度是变化的

每条都能想办法绕，但绕完都不优雅。所以论文换了个思路：用一组数值有界、又天然携带相对距离的向量。

正弦位置编码

公式乍看很吓人，拆成两半就好懂了：偶数维用 sin，奇数维用 cos。

关键在于「两两分组」：把 512 维分成 256 组，每组两个数（一个 sin、一个 cos），共用同一个频率。

拿 d_model = 8 演示，就有 4 组，i = 0,1,2,3：

组 i 分母 10000^(2i/8) 该组算出的两个值
0 1 sin(pos/1), cos(pos/1)
1 10 sin(pos/10), cos(pos/10)
2 100 sin(pos/100), cos(pos/100)
3 1000 sin(pos/1000), cos(pos/1000)

pos = 3 的时候，这 8 个数字就是：

越往后，分母越大，sin/cos 转得越慢，取值变化越平缓。

时钟比喻：快针管近处，慢针管远处

为什么要有快有慢？因为只有一种频率，就会周期性重复。

  • 变化快的维度（靠前）：隔几个位置就转了整整一圈，适合分辨「相邻的两个词」——但走远了就分不清了；
  • 变化慢的维度（靠后）：近处几乎一样，走得越远差别才越明显，适合分辨「这句话有多长」。

合起来就像一块表：秒针走得快、时针走得慢，只看秒针不知道几点，只看时针分不清分钟，几根针配合起来才能读出准确时刻。

位置编码是同一套逻辑：不同频率的维度搭配，近处和远处才能同时区分开。

为什么点积能算出距离

这是这套设计最妙的地方——考前几步就能对上 Transformer 的运算方式。

假设位置 pos 和位置 pos + k，两组编码做点积，结果只和 k 有关，和 pos 本身无关。也就是说：

模型不需要知道「我是第几个」，只需要从点积结果里读出「我们隔得多远」。而 attention 本来就是靠点积工作的——位置信息就这么自然地被算进相关性里了。

但今天的大模型都不用这个了

原始论文的做法有个隐患：位置向量和语义向量直接相加，两者混在一起再投影出 Q、K、V。此时 Q 和 K 里既有语义又有位置，点积出来的结果就不再是纯粹的距离关系，得靠模型自己去学怎么拆开。

现在的做法是 RoPE（旋转位置编码），思路换了一下：

正弦位置编码（论文原版） RoPE（现在的主流）
位置怎么进去 生成位置向量，和 embedding 相加 不生成额外向量，直接旋转 Q 和 K
影响范围 输入一变，Q、K、V 全被影响 只旋转 Q、K，不碰 V
位置性质 绝对位置 相对位置
额外参数 无 无，维度也不变

RoPE 的具体做法是：把 Q 相邻两个维度拼成二维向量，按位置乘一个旋转矩阵（里面还是 sin/cos），位置越靠后转的角度越大，不同维度用不同频率。K 也一样处理。

关键在于：Q 和 K 都转过之后，共同的绝对旋转在点积里会相互抵消，剩下的只有两者的相对差距。这样一来，无论语义是什么，分数里出现的只有相对距离，模型不用再自己学这件事，训练也就简单一些。

那 V 为什么不用转？因为 V 根本不参与「算关系」。Q 和 K 相乘得出的是「该取多少」，V 只是被按比例取走的内容——它不需要知道位置。

小结

  1. RNN 靠串行天然携带顺序，Transformer 靠并行换来了速度，也丢了顺序。
  2. 位置编码不是装饰，是「dog bites man ≠ man bites dog」能被区分的前提。
  3. 用加法不用拼接，是为了让 d_model 保持恒定，后面的模块才好衔接。
  4. 不用整数编号，是因为模型只会点积不会减法，而且大数值会淹没语义。
  5. 正弦编码用不同频率的两两分组，像表针一样近远兼顾。
  6. 它最漂亮的性质是：两个位置的点积只取决于它们相隔多远。
  7. 现在基本都用 RoPE：旋转 Q 和 K、不碰 V，得到的是相对位置，还不增加参数。

一句话记住分工：attention 负责建立 token 之间的关系，位置编码负责告诉它这些 token 的前后顺序。
