uv + ruff + ty：一套现代 Python 工具链

文章发布时间:
2026-11-15

参考视频：《现代 Python 工具链：uv、ruff、ty》（B 站「AI日日新」，8 分钟）。

一句话：uv 管环境与依赖，ruff 管格式与 lint，ty 管类型 —— 三个 Rust 工具拼起来，替掉 pip + venv + flake8 + isort + black + mypy 那一整排，让 Python 项目的初始化、装包、检查都快到不用等。

一、三个工具，各管一段

工具 负责 替代掉
uv 包与项目管理、虚拟环境、Python 版本 pip、venv、pip-tools、poetry 的一部分
ruff lint + 格式化（含 import 排序） flake8、isort、black、pyupgrade
ty 类型检查 + 语言服务器 mypy、Pyright、Pylance

三者同属 Astral。顺带记一笔背景：Astral 已在 2026 年 3 月被 OpenAI 收购，官方承诺工具继续开源（MIT）。视频里只说了「同一家公司」，这条算补充。

成熟度上得说实话：uv 和 ruff 现在可以直接上，ty 还在 Beta（2025 年 12 月发布 Beta，至今仍是 0.0.x 版本号）。ty 已经能替代 mypy 的日常用法，但规则覆盖率还在补，建议先和现有类型检查并行跑一段。

两个容易混的点：

  • pip install uv 这一步的下载走的是 pip 自己的镜像配置，和 uv 的索引无关。uv 的索引只影响 uv add / uv lock / uv sync 去哪个源找包。
  • 这条环境变量不必长期手动维护：uv init 之后第一次 uv add 时，uv 会把当前生效的默认索引写进 pyproject.toml（就是下面那张 [[tool.uv.index]] 表，default = true）。所以项目一提交，换台机器不用再配环境变量也能复现 —— 视频里「包管理文件会记录镜像源」说的就是这件事。

四、虚拟环境：uv venv 其实可以省

视频说「初始化项目后还需要创建虚拟环境」。在 uv 的工作流里这一步是自动的：uv add、uv run、uv sync 发现没有 .venv 都会自己建一个（0.13.8 实测 uv sync 直接输出 Creating virtual environment at: .venv）。

手动 uv venv 只在两种场合需要：想指定解释器（uv venv --python 3.12），或想指定别的目录。

另外平时也不用 activate。uv run main.py 会自动用项目环境、必要时先同步依赖再跑。只有要进交互式 REPL、或者让 GUI 调试器挂上去的时候才激活：

日常就这几条：

几个值得写进笔记的细节：

  • uv.lock 要提交进 git。它是跨平台的通用锁文件（不是只锁当前机器），并且记录了每个包的 hash。
  • CI 用 uv sync --frozen：只按锁装、不尝试更新锁；锁文件和 pyproject.toml 对不上时直接失败，避免线上悄悄换了版本。
  • 升级依赖是单独的动作：uv lock --upgrade（全升）或 uv lock --upgrade-package numpy（单升）。
  • uv add 默认用「兼容」范围写依赖（numpy>=2.5.0），精确版本记录在 uv.lock 里 —— 这正是它比 pip install 稳的地方。

视频里 uv add numpy 装到 numpy==2.5.0，uv add --dev ruff 装到 ruff==0.15.20；画面上 uv run main.py 直接输出了 Hello from uv-ruff-ty!。

六、PyTorch 这类要专用索引的包（视频重点，也最容易踩坑）

原因：PyPI 上 torch 的默认 wheel 带 CUDA，CPU 版轮子只发布在 PyTorch 自己的索引里。所以要告诉 uv「torch 去那个源找」。写进 pyproject.toml 的写法（已订正，见下方警告）：

三个字段的含义，看懂了就不会乱改：

  • default = true：这条是默认索引，等价于把 UV_DEFAULT_INDEX 写进项目。
  • explicit = true：这条索引只给显式点名它的包用，不会拿去解析别的包 —— 防止 PyTorch 镜像里那几个同名包污染正常的依赖解析。
  • [tool.uv.sources]：把 torch 钉到 pytorch-cpu 这条索引上。

⚠️ 订正：视频 README 里给的示例是两段同名的 [tool.uv.index] 表头。TOML 不允许同名表重复定义，照抄会得到 Cannot declare ('tool', 'uv', 'index') twice，整个 pyproject.toml 直接解析失败（我用 Python 的 tomllib 验证过；uv 自己生成的写法也是数组表 [[tool.uv.index]]）。多个索引必须写成数组表。视频里实际的 pyproject.toml 只有一条镜像索引，所以当时没炸 —— 但 README 那段示例是错的。

ty 立刻在编辑器里标红，报错原文：

Function always implicitly returns None, which is not assignable to return type str

info: Consider changing the return annotation to -> None or adding a return statement

这段其实藏了两个错误：函数声明返回 str 但实际没有 return（永远返回 None）；调用 main() 时又漏传了 name 参数。ty 两个都会指出。

一个必须知道的副作用：装 ty 扩展后，它会默认把 python.languageServer 设为 "None"，也就是主动接管 Pylance 的位置（避免两个语言服务器打架）。如果你还想留着 Pylance 的补全和悬停提示、只用 ty 做检查，得手动把这个设置改回去。

ty 是 Astral 对标 mypy / Pyright / Pylance 的产品，但仍在 Beta。稳妥的过渡方式：CI 里先只对新增代码卡 ty check，和 mypy 并行跑一两个月再决定要不要完全替换。
